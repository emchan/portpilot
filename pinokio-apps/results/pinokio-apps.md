## Method and limitations

- **Sources:** GitHub API metadata plus a full-source snapshot of every repository (default branch `main`), resolved on 2026-11-20. The exact commit SHA analyzed for each repository is recorded in its per-app report below. Two repositories (`y`, `factory`) are empty.
- **Dependencies:** all `requirements*.txt` files (root or nested), plus install commands in `install.js`, `torch.js`, `start.js` and `update.js`. Version numbers, pip/conda flags, index URLs and local paths are stripped; duplicate packages are merged. For repos without a requirements file, third-party Python imports in local `.py` files are used as a fallback signal. CUDA-only packages are also detected from those imports when a CUDA-specific library is used directly in the wrapper source.
- **Platform support:** explicit `[NVIDIA ONLY]`, `[MAC ONLY]`, `Cross Platform`, etc. tags in `pinokio.js` descriptions, GitHub descriptions and READMEs take precedence; otherwise the GPU branches in `torch.js` and the presence of raw CUDA APIs or CUDA-pinned wheels are used.
- **Porting difficulty:** a heuristic score combining the platform restriction, the number and weight of CUDA-only dependencies (halved when optional), missing AMD/Mac routes in `torch.js`, and any CUDA code in the wrapper repository. It estimates integration effort, not runtime performance.
- **CUDA footprint:** these are Pinokio launcher repositories, not the upstream applications they install. No `.cu`/`.cuh` files, `__global__` kernels or `@triton.jit` kernels were found, so kernel and CUDA-line counts are zero; the CUDA work lives in the upstream app or in PyTorch wheels. `torch.cuda.*` calls and raw CUDA driver/runtime API names found in the wrapper scripts are listed in the per-app reports.
- Optional dependencies are marked *(optional)* and are excluded from the difficulty weight as much as possible; they can still block a port if a user enables them.
